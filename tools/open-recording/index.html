The meeting is the part
an agent could never reach.

The reason is mundane: Node cannot open a microphone. And a transcription API means sending the conversation in the room to somebody else's server — which, for a lot of meetings, was never on the table. open-recording takes neither option: the browser holds the microphone, the dev server holds the state, and whisper.cpp does the transcription locally. The audio never leaves the machine.

01  Why

The microphone is in the browser.
The state is on the server.

That is the one design premise of the whole thing, not a backend version that has yet to be written. Only a real tab can reach a microphone, so recording has to happen in the browser — but if the session, the files and the transcript lived there too, closing the tab would take all of it. So the state stays on the dev server and the page only records. That split is also what lets a person and an agent drive the same recorder.

Nothing leaves the machine

whisper.cpp runs on your own CPU. The audio, the transcript and the notes are files in your own folder — not "we won't train on it", but no upload step at all.

One recorder, two drivers

A person and an agent share the session. Whoever presses stop, the other sees it, because there is only ever one state machine — not two that drift.

Recordings are directories

One recording is one directory: the audio, timed segments, a Markdown transcript, the notes. No database, no index — ls shows you everything there is.

Traditional Chinese, if you ask

Whisper writes Simplified whatever was spoken; its training data is. Set the script and OpenCC converts phrase by phrase — 软件 becomes 軟體, not 軟件 — and the timestamps survive it.

02  For agents

Press record over MCP.

Point the agent at http://localhost:5274/mcp. A round usually looks like this: start the recording, let the meeting happen, stop it with transcribe: true, read the transcript back, write the summary into the notes beside the audio.

start_recordingPress record. Returns only once the browser confirms the microphone is actually open.
stop_recordingStop and finalize; pass transcribe: true to run whisper while it is at it.
read_transcriptTimestamped Markdown, plain text, or timed segments.
search_transcriptsSearch across every transcript, with millisecond offsets.
write_notesPark a summary or action items beside the audio.
recorder_statusIs anything recording, and is a studio connected to record through.

A finished meeting — and the summary the agent wrote into notes.md afterwards.

It will not lie about recording. start_recording waits until the studio reports that MediaRecorder is genuinely running. Tab closed, microphone blocked — the agent gets a refusal that says which. A tool that answers "done" for a recording nobody is making is the worst way this kind of thing can fail, so it refuses instead.

03  Get started

Two commands, then arm the microphone once.

Recording works with nothing else installed. Only transcription needs whisper.cpp and ffmpeg — and whatever is missing, doctor prints the fix next to it.

# studio at :5274, MCP endpoint at /mcp
npx open-recording dev --mcp

# optional — local transcription
brew install whisper-cpp ffmpeg
npx open-recording doctor
