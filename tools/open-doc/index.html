The doc framework built for agents.

A React-first document framework. Every page renders to a real A4 sheet. Outline, contents and page numbers maintain themselves. Export a PDF that looks designed.

$ npx @open-document/cli init my-docs

The viewer — page thumbnails, a real A4 sheet, and the design panel

01 · Why

A page is a sheet. Not an approximation.

An agent hands you Markdown; you need a file you can send. The layout layer in between cannot be handled through conversation. Let the agent write React, and leave the paper to the framework.

01 · PAPER

A4 is A4.

794 × 1123 px @96dpi. The @page size matches, so screen and printer produce the same document.

02 · NUMBERING

Numbering maintains itself.

Outline, contents and page numbers update as the document changes. Nobody has to remember.

03 · PAGINATION

Pagination knows what not to break.

Content flows to the next sheet on its own. Headings stay with their text, tables stay whole.

04 · CHECKS

Layout problems come back as words.

Overflow, a missing image, a broken table — reported in a form the agent can read.

02 · How

Author a doc with your agent. Three steps from empty folder to PDF.

Scaffold the workspace, describe what you need, take the file.

01 · INIT

Spin up a workspace

Creates the document workspace. Every report you author lives inside it.

$ npx @open-document/cli init my-docs
✓ ready
02 · PROMPT

Ask your agent

Your agent drafts pages as React components. You guide with prompts. It will not invent your numbers.

/create-doc our Q3 infrastructure review
03 · EXPORT

Download the PDF

One menu: PDF or HTML. Headless export runs the same path in CI.

$ open-doc export --pdf
→ q3-review.pdf
03 · For agents

Bring your own agent. 23 tools, one endpoint.

Point it at localhost:5273/mcp — stateless Streamable HTTP, no handshake. The tools cover documents, text edits, layout checks, page screenshots, Markdown import, export, themes and assets.

01 · ONE SOURCE

Stale writes get a 409.

People and agents share one implementation. write_document takes the version you last read and never overwrites whoever got there first.

02 · CONTEXT

It edits the page you are reading.

The dev server publishes where you are reading. The agent picks up that sheet without asking which one.

03 · INSPECT

Click. Edit. Saved.

Toggle inspect, click any element, change the text. The edit is written back through an AST replacement and the page reloads.

04 · COMMENTS

Leave a comment. Run /apply-comments.

Notes are pinned as markers in your source. The agent edits exactly what you flagged, then clears them.

04 · Get started

Ship a report in the next minute. One command, zero config.

Free and open source under the MIT license, published on npm. Your agent takes it from here.

# scaffold a workspace
$ npx @open-document/cli init my-docs

# studio at :5273, MCP endpoint alongside it
$ open-doc dev --mcp

open-doc's skeleton comes from open-slide by @1weiho — the ops layer shared by the dev API and an MCP server, the Vite-plugin dev server, the two-pane shell, all of it came from there. If open-slide is Google Slides for agents, open-doc is Google Docs: same idea, different medium. The same architecture runs open-recording.
