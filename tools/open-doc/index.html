An agent can write the report.
It cannot lay one out.

What was missing was never the prose. It is the actual size of an A4 sheet, page numbers that move with the content, a heading that should not land at the foot of a page. Nobody wants to do any of that by hand — and without it, the file cannot simply be sent. That is the part open-doc covers: your coding agent writes the React, the framework takes the rest.

01  Why

The problem was never generation.
It was the file you have to send.

Ask an agent for a quarterly report and what comes back is a block of Markdown. Between that and something you can actually send sits a whole layer of layout work — and that layer cannot be handled through conversation. open-doc changes the medium instead: let the agent write React, because that is what it is genuinely good at, and leave the paper to the framework.

A page is really a sheet

A4 is 794 × 1123 px @96dpi, not "roughly that big". The @page size matches, so what you see on screen and what comes out of the printer are the same document — nothing is rescaled in between.

Numbering maintains itself

Outline, contents and page numbers stay correct as the document changes. This is exactly the kind of thing that, done by hand, someone always forgets to update.

Pagination knows what not to break

Content flows to the next sheet on its own, and knows a heading should not be separated from its text, or a table split down the middle.

Layout problems come back as words

An agent cannot see the page. So overflow, a missing image, a broken table — open-doc says so in a form it can read, instead of leaving it to guess.

02  How

Three commands, one real document.

Scaffold the workspace, describe what you need, take the file. The agent handles the middle.

01  INIT

Scaffold

One command sets up the workspace, the dev server, and the skills your agent reads.

02  PROMPT

Describe it

/create-doc settles topic, audience and source material before it writes a word — it will not invent your numbers for you.

03  EXPORT

Take the file

One Download menu: PDF or HTML. For CI, headless export runs the same path.

# scaffold a workspace
npx @open-document/cli init my-docs

# studio at :5273, MCP endpoint alongside it
open-doc dev --mcp
03  For agents

23 tools, one endpoint.

Point the agent at http://localhost:5273/mcp and that is the whole setup — stateless Streamable HTTP, no session handshake. The tools cover the documents themselves, surgical text edits, layout checks and page screenshots, Markdown import, export, themes, assets and folders.

People and agents share one implementation

Not two sets of logic drifting apart. So write_document takes the version you last read, and answers a stale write with 409 instead of quietly overwriting whoever got there first.

It edits the page you are reading

The dev server publishes where you are, so the agent picks up that sheet — no round trip to establish which page you meant.

See something wrong, fix it there

Inspect mode edits text on the page; the change is written back through an AST replacement and the page reloads. No hunting for which file, which line.

Or just leave a sentence

Comments are stored as markers in the source until /apply-comments walks them all. For when you would rather not stop reading to fix things.
