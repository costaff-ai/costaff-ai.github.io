open-doc

The document framework
built for agents.

Describe the report you need in natural language — your coding agent writes the React. open-doc handles the page geometry, the outline, the table of contents, page numbers, print layout, and export.

01  Why

Reports are the output
nobody wants to format.

Agents write excellent prose and terrible Word documents. open-doc gives the agent a medium it is actually good at — React — and gives you a PDF that looks like a designer made it.

Real page geometry

Every page renders into a true sheet: A4 (794 × 1123 px @96dpi), Letter, A5 or Legal, portrait or landscape. The @page size matches, so nothing is rescaled at print time.

Furniture that maintains itself

Outline, table of contents and page numbers stay correct as the document changes — nobody renumbers anything by hand.

Auto-pagination with judgement

Content flows onto new sheets on its own, and knows what not to break across a page boundary.

Layout checks

An agent cannot see the page, so open-doc reports what went wrong — overflow, a missing image, a broken table — in words it can act on.

02  How it works

Three commands to a real document.

Scaffold a workspace, ask your agent for the document, and read the result as a live A4 sheet in the browser.

01  INIT

Scaffold

One command creates the workspace, the dev server and the skills your agent reads.

02  PROMPT

Ask

/create-doc establishes topic, audience and source material first — it will not invent your numbers — then plans and writes the pages.

03  EXPORT

Hand it over

One Download menu: PDF or HTML. Headless export runs the same path without a browser.

# scaffold a workspace
npx @open-document/cli init my-docs

# studio at :5273, MCP endpoint alongside it
open-doc dev --mcp
03  For agents

An MCP server, so any agent can drive it.

open-doc dev --mcp mounts an MCP endpoint next to the UI — 23 tools covering documents, surgical text edits, layout checks and page screenshots, Markdown import, export, themes, assets and folders. Stateless Streamable HTTP, so a client just points at http://localhost:5273/mcp with no session handshake.

The tools and the browser share one implementation

So write_document takes the content you last read, and refuses a stale write with 409 rather than overwriting whoever got there first.

It edits the page you are reading

The dev server publishes where you are in the document, so your agent edits the sheet you are looking at instead of asking which one you meant.

Edit on the page

Inspect mode selects any element and rewrites its text — the edit lands back in the source through an AST replacement, and the page hot-reloads.

Leave a note instead

Comments are stored as markers in the source; /apply-comments walks them, makes each edit, and clears the markers.
