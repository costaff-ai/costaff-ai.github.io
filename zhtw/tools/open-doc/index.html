The doc framework built for agents.

React 優先的文件框架。每一頁都渲染成真正的 A4 紙。大綱、目錄與頁碼自己維持正確。匯出一份像設計師做的 PDF。

$ npx @open-document/cli init my-docs

檢視器 — 左側頁面縮圖，中間一張真正的 A4 紙，右側是設計面板

01 · 為什麼

一頁就是一張紙。 不是近似值。

Agent 給你的是 Markdown，你要的是能寄出去的檔案。中間那層版面工作，用對話處理不完。讓 agent 寫 React，紙張交給框架。

01 · 紙張

A4 就是 A4。

794 × 1123 px @96dpi。@page 尺寸跟著對齊，螢幕上與印出來的是同一份。

02 · 頁碼

頁碼自己會算。

大綱、目錄與頁碼隨內容變動自動更新。不必有人記得回頭改。

03 · 分頁

分頁知道什麼不該斷。

內容自己流到下一頁。標題不跟內文分家，表格不從中間裂開。

04 · 檢查

版面問題用文字回報。

溢出、圖片沒載入、表格破版——open-doc 用 agent 讀得懂的方式講出來。

02 · 怎麼用

和你的 agent 一起寫文件。 從空資料夾到一份 PDF，三步。

建工作區、描述你要的東西、把檔案拿走。

01 · INIT

建一個工作區

建立文件工作區。之後每一份報告都住在裡面。

$ npx @open-document/cli init my-docs
✓ 就緒
02 · PROMPT

交給你的 agent

Agent 把每一頁寫成 React 元件，你用 prompt 引導。它不會替你編數字。

/create-doc 第三季基礎架構回顧
03 · EXPORT

下載 PDF

一個選單：PDF 或 HTML。CI 上的 headless 匯出走同一條路徑。

$ open-doc export --pdf
→ q3-review.pdf
03 · 給 agent

換成你自己的 agent 也行。 23 個工具，一個 endpoint。

指向 localhost:5273/mcp 就結束了，無狀態 Streamable HTTP。工具涵蓋文件、文字修改、版面檢查、頁面截圖、Markdown 匯入、匯出、主題與資產。

01 · 一致

過期的寫入會拿到 409。

人與 agent 共用同一份實作。write_document 認你最後讀到的版本，不會蓋掉先到的人。

02 · 定位

它改你正在看的那一頁。

Dev server 會公開你讀到哪一頁，agent 直接接手，不必問你指的是第幾頁。

03 · 編輯

點一下，改，存檔。

開啟 Inspect，點任一元素改文字。改動透過 AST 寫回原始碼，頁面即時更新。

04 · 註記

留一則註記，讓 agent 去改。

註記以標記形式存在原始碼裡。跑 /apply-comments，agent 逐一改完並清掉標記。

04 · 開始使用

一分鐘後交出一份報告。 一個指令，零設定。

開源、MIT 授權、已發佈在 npm。每一行都能讀、能改、能拿去用。

# 建立工作區
$ npx @open-document/cli init my-docs

# 工作室在 :5273，MCP endpoint 就掛在旁邊
$ open-doc dev --mcp
在 GitHub 上查看 @open-document/core 其他工具

open-doc 的骨架來自 @1weiho 的 open-slide——dev API 與 MCP server 共用的 ops 層、以 Vite plugin 存在的 dev server、雙欄外殼，都是從那裡來的。如果 open-slide 是給 agent 用的 Google Slides，open-doc 就是 Google Docs：同一個想法，換一種媒介。同一套架構也用在 open-recording 上。
