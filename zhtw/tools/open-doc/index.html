01 · 為什麼

螢幕上是什麼， 印出來就是什麼。

Agent 給你的是一段 Markdown，你要的是能直接寄出去的檔案。中間那層版面工作沒辦法用對話交代清楚——所以讓 agent 寫 React，紙張的事交給框架。

01 · 紙張

印出來就是你看到的樣子

A4 就是 794 × 1123 px，跟印表機認的同一個尺寸。不會發生「螢幕上好好的，印出來整個跑掉」這種事。

02 · 頁碼

加一節，目錄自己跟上

插入一個章節，目錄和頁碼立刻重編。你不用回頭檢查任何一個數字。

03 · 分頁

表格不會被切成兩半

寫滿了就自己換頁，但標題會跟著它的段落走，表格不會從中間裂開。

04 · 檢查

哪裡爆版，它會直接說

Agent 看不到頁面，所以 open-doc 直接告訴它：第 7 頁的表格超出 40px、第 3 頁有張圖沒載入。

02 · 怎麼用

和你的 agent 一起寫文件。 從空資料夾到一份 PDF，三步。

建工作區、描述你要的東西、把檔案拿走。

01 · INIT

建一個工作區

建好文件工作區。之後每一份報告都住在這個資料夾裡。

$ npx @open-document/cli init my-docs
✓ 就緒
02 · PROMPT

交給你的 agent

Agent 把每一頁寫成 React 元件，你用一句話引導。要它引用數據，它會問你要來源，不會自己編。

/create-doc 第三季基礎架構回顧
03 · EXPORT

下載 PDF

按一下就下載 PDF 或 HTML。要接 CI 的話，headless 匯出走的是同一條路。

$ open-doc export --pdf
→ q3-review.pdf
03 · 給 agent

換成你自己的 agent 也行。 23 個工具，一個 endpoint。

指向 localhost:5273/mcp 就結束了，無狀態 Streamable HTTP。工具涵蓋文件、文字修改、版面檢查、頁面截圖、Markdown 匯入、匯出、主題與資產。

01 · 一致

兩邊同時改，不會蓋掉對方

你在頁面上改字的同時 agent 也在寫，這種事一定會發生。它認你最後讀到的版本，衝突時回 409 而不是安靜覆蓋。

02 · 定位

說「這一頁」它就知道是哪頁

Dev server 知道你正在讀第幾頁。所以你說「這頁的圖換掉」，agent 不會反問你是哪一頁。

03 · 編輯

點一下就能改字

開 Inspect 模式，點任何一個元素直接改。改完寫回原始碼，頁面即時更新——不用去翻是哪個檔案第幾行。

04 · 註記

懶得改？留一句話就好

在頁面上留註記，它會釘在原始碼裡。之後跑 /apply-comments，agent 一次改完你標的每一處。

一份文件就是一個檔案。就是 React，沒別的。

docs/<id>/index.tsx 就是那份報告本身。沒有專有格式，git diff 得出來，你的 agent 也讀得懂。

04 · 開始使用

一分鐘後交出一份報告。 一個指令，零設定。

一個指令就開始，不用設定任何東西。MIT 授權，已經在 npm 上，接下來交給你的 agent。

# 建立工作區
$ npx @open-document/cli init my-docs

# 工作室在 :5273，MCP endpoint 就掛在旁邊
$ open-doc dev --mcp
在 GitHub 上查看 @open-document/core 其他工具
