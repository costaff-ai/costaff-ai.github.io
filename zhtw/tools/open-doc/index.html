Agent 寫得出報告，
排不出版面。

缺的從來不是文筆。缺的是 A4 的實際尺寸、是目錄頁碼要跟著內容一起動、是標題不該落在頁尾。這些事沒有人想手動處理，但少了它們，那份檔案就不能直接寄出去。open-doc 補的就是這一段：你的 coding agent 寫 React，剩下的交給框架。

01  為什麼

問題不在生成，
在那份要交出去的檔案。

請 agent 寫一份季度報告，它給你的多半是一段 Markdown。要變成能寄出去的東西，中間還隔著一整層版面工作——而那層工作，用對話是處理不完的。open-doc 的做法是換一個媒介：讓 agent 寫 React，因為那是它真正擅長的；紙張這件事，交給框架。

頁面是真的紙

A4 是 794 × 1123 px @96dpi，不是「差不多這麼大」。@page 尺寸跟著對齊，所以螢幕上看到的和列印出來的是同一份，中間不會被重新縮放。

頁碼自己會算

大綱、目錄、頁碼隨內容變動自動維持正確。這是那種一旦要手動做，就一定會忘記更新的東西。

分頁知道什麼不該斷

內容滿了會自己流到下一頁，而且知道標題不該跟內文分家、表格不該從中間裂開。

版面問題用文字回報

Agent 看不到頁面。所以溢出、圖片沒載入、表格破版這些事，open-doc 用它讀得懂的方式講出來，而不是讓它猜。

02  怎麼用

三個指令，一份真的文件。

建工作區、描述你要的東西、把檔案拿走。中間那段 agent 自己會處理。

01  INIT

建工作區

一行指令，把工作區、dev server 與 agent 要讀的 skills 一起建好。

02  PROMPT

描述你要的

/create-doc 會先問清楚主題、受眾與素材來源，確認過才動筆——它不會替你把數字編出來。

03  EXPORT

把檔案拿走

一個下載選單，PDF 或 HTML。要進 CI 的話，headless 匯出走的是同一條路徑。

# 建立工作區
npx @open-document/cli init my-docs

# 工作室在 :5273，MCP endpoint 就掛在旁邊
open-doc dev --mcp
03  給 agent

23 個工具，一個 endpoint。

把 agent 指到 http://localhost:5273/mcp 就結束了——無狀態的 Streamable HTTP，沒有 session 握手這回事。工具涵蓋文件本身、精準的文字修改、版面檢查與頁面截圖、Markdown 匯入、匯出、主題、資產與資料夾。

人跟 agent 共用同一份實作

不是兩套邏輯各改各的。所以 write_document 認你最後讀到的版本，遇到過期的寫入回 409，而不是安靜地蓋掉先到的人。

它改的是你正在看的那一頁

Dev server 會把「你讀到哪」寫出來，agent 直接接手那一頁，省掉「你說的是第幾頁」這種來回。

看到哪裡不對就直接改

Inspect 模式點下去就能改文字，改完透過 AST 寫回原始碼，頁面即時更新——不必回去翻是哪個檔案的第幾行。

也可以只留一句話

註解存成原始碼裡的標記，等 /apply-comments 一次走完。適合看的時候懶得改、想一次交給 agent 的情況。

04  開始使用

開源，MIT，已經在 npm 上。

每一行都能讀、能改、能拿去用。

在 GitHub 上查看 npm 上的 @open-document/core 其他工具

open-doc 的骨架來自 @1weiho 的 open-slide——dev API 與 MCP server 共用的 ops 層、以 Vite plugin 存在的 dev server、雙欄外殼，都是從那裡來的。如果 open-slide 是給 agent 用的 Google Slides，open-doc 就是 Google Docs：同一個想法，換一種媒介。
