open-doc

為 agent 打造的
文件框架。

用自然語言描述你要的報告，你的 coding agent 負責寫 React；頁面尺寸、大綱、目錄、頁碼、列印版面與匯出，都交給 open-doc。

01  為什麼

報告，是沒有人想排版的產出。

Agent 寫得出優秀的文字，卻做不出像樣的 Word 檔。open-doc 給 agent 一個它真正擅長的媒介——React——然後給你一份看起來像設計師做的 PDF。

真正的頁面尺寸

每一頁都渲染成一張真的紙：A4（794 × 1123 px @96dpi）、Letter、A5 或 Legal，直式或橫式。@page 尺寸相符，所以列印時不會被重新縮放。

自己維護的頁面元素

大綱、目錄與頁碼會隨著文件變動保持正確，沒有人需要手動重編號碼。

知道什麼不該斷的自動分頁

內容會自己流到新的一頁，並且知道哪些東西不該被跨頁切斷。

版面檢查

Agent 看不到頁面，所以 open-doc 用它能理解的文字回報問題——溢出、圖片沒載入、表格破版。

02  怎麼運作

三個指令，一份真的文件。

建立工作區、向 agent 描述你要的文件，然後在瀏覽器裡讀到一張活的 A4 紙。

01  INIT

建立

一行指令建好工作區、dev server，以及 agent 會讀的 skills。

02  PROMPT

描述

/create-doc 會先確立主題、受眾與素材來源——它不會編造你的數字——再規劃並寫出每一頁。

03  EXPORT

交付

一個下載選單：PDF 或 HTML。Headless 匯出走同一條路徑，不需要瀏覽器。

# 建立工作區
npx @open-document/cli init my-docs

# 工作室在 :5273，MCP endpoint 就掛在旁邊
open-doc dev --mcp
03  給 agent 用

一個 MCP server，任何 agent 都能操作。

open-doc dev --mcp 會在 UI 旁邊掛上 MCP endpoint——23 個工具，涵蓋文件、精準文字編輯、版面檢查與頁面截圖、Markdown 匯入、匯出、主題、資產與資料夾。無狀態的 Streamable HTTP，客戶端只要指向 http://localhost:5273/mcp，不需要任何 session 握手。

工具與瀏覽器共用同一套實作

所以 write_document 接的是你最後讀到的內容，遇到過期的寫入會回 409，而不是直接覆蓋掉先到的人。

它會編輯你正在看的那一頁

Dev server 會把你讀到文件的哪個位置公開出來，所以 agent 直接改你正在看的那張紙，不必反問你指的是哪一頁。

直接在頁面上改

Inspect 模式可以選取任一元素並改寫文字，編輯透過 AST 替換寫回原始碼，頁面即時熱更新。

或者留一則註記

註解會以標記的形式存在原始碼裡；/apply-comments 會逐一走過、完成每個編輯，然後清掉標記。

04  開始使用

開源、MIT 授權、已發佈在 npm。

每一行都能讀、能改、能拿去用。

在 GitHub 上查看 npm 上的 @open-document/core 所有工具

open-doc 沿襲自 @1weiho 的 open-slide——由 dev API 與 MCP server 共用的 ops 層、以 Vite plugin 形式存在的 dev server、以及雙欄外殼，都來自於它。如果說 open-slide 是給 agent 用的 Google Slides，那 open-doc 就是 Google Docs：概念相同，媒介不同。
