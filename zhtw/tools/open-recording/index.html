open-recording

在瀏覽器錄音，
在你的機器上轉錄。

open-recording 給 agent 一顆真正的錄音鍵：它按下開始，瀏覽器裡的工作室頁面接管麥克風；按下停止，音檔就落在你的磁碟上，並交給 whisper.cpp 轉錄。音訊完全不離開這台機器。

01  為什麼

會議，是 agent 一直碰不到的那份產出。

Node 開不了麥克風，而用轉錄 API 等於把會議室裡的對話送到別人的伺服器。open-recording 兩個都解決：瀏覽器持有麥克風，dev server 持有狀態，轉錄則由 whisper.cpp 在本機完成。

沒有東西離開這台機器

whisper.cpp 跑在你自己的 CPU 上。音檔、逐字稿與筆記都是你自己資料夾裡的檔案——根本沒有一個上傳步驟需要你去關掉。

一台錄音機，兩個操作者

人與 agent 共用同一個 session。不管是誰按下停止，另一邊都會看到——因為從頭到尾只有一個狀態機。

錄音是資料夾，不是資料列

每一段錄音裡有它的音檔、帶時間的片段、Markdown 逐字稿與筆記。沒有資料庫、沒有索引——檔案系統就是事實本身。

需要的話，輸出繁體中文

不管講的是什麼，Whisper 一律寫出簡體。設定字體之後，逐字稿會以詞彙為單位轉換，讓台北開的會，讀起來就是會議室裡的人在寫的字。

02  給 agent 用

用 MCP 按下錄音。

把你的 agent 指向 http://localhost:5274/mcp。典型的一輪是：開始錄音 → 會議進行 → 帶 transcribe: true 停止 → 讀回逐字稿 → 把摘要寫在音檔旁邊的筆記裡。

start_recording按下錄音。只有在瀏覽器確認麥克風已開啟後才回傳。
stop_recording停止並收尾；帶 transcribe: true 就立刻跑 whisper。
read_transcript帶時間戳的 Markdown、純文字，或帶時間的片段。
search_transcripts跨所有逐字稿的子字串搜尋，附毫秒位移。
write_notes把摘要或待辦寫在音檔旁邊。
recorder_status現在有沒有東西在錄，以及有沒有工作室可以錄。

一段完成的錄音——以及 agent 寫在音檔旁邊 notes.md 裡的摘要。

它不會謊報自己在錄音。 start_recording 會等到工作室頁面回報 MediaRecorder 真的跑起來才回傳。如果分頁被關掉、或麥克風被擋，agent 收到的是一個講明原因的拒絕——絕不會為一段根本沒在錄的錄音回報成功。

03  開始使用

兩個指令，然後授權一次麥克風。

不裝任何其他東西也能錄音。只有轉錄需要 whisper.cpp 與 ffmpeg——而 doctor 會把每一項缺件的修法印出來。

# 工作室在 :5274，MCP endpoint 在 /mcp
npx open-recording dev --mcp

# 選用——本機轉錄
brew install whisper-cpp ffmpeg
npx open-recording doctor
