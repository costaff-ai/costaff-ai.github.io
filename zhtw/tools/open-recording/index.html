會議這一段，
agent 一直碰不到。

原因很實際：Node 開不了麥克風。而用轉錄 API，等於把會議室裡的對話送到別人的伺服器上——很多會議一開始就不該這樣處理。open-recording 兩個都不選：瀏覽器持有麥克風，dev server 持有狀態，轉錄交給本機的 whisper.cpp。音訊從頭到尾沒有離開這台機器。

01  為什麼

麥克風在瀏覽器，
狀態在伺服器。

這是整套東西唯一的設計前提，不是還沒做成純後端版本。麥克風只有真實的分頁拿得到，所以錄音必須發生在瀏覽器；但 session、檔案、逐字稿如果也散在前端，關掉分頁就什麼都沒了。於是狀態全部留在 dev server，前端只負責錄——這也讓人跟 agent 能操作同一台錄音機。

沒有東西離開這台機器

whisper.cpp 跑在你自己的 CPU 上。音檔、逐字稿、筆記都是你資料夾裡的檔案——不是「我們不會拿去訓練」，是根本沒有上傳這個步驟。

一台錄音機，兩個操作者

人跟 agent 共用同一個 session。誰按停止，另一邊都看得到，因為從頭到尾只有一個狀態機——不是兩份各自為政的狀態。

錄音是資料夾，不是資料列

一段錄音就是一個目錄，裡面有音檔、帶時間的片段、Markdown 逐字稿與筆記。沒有資料庫、沒有索引，ls 一下就是全部。

需要的話輸出繁體

不管講的是什麼，Whisper 一律寫簡體——它的訓練資料就是這樣。設定之後會用 OpenCC 做詞彙級轉換，软件 變成軟體而不是軟件，時間戳也不會跑掉。

02  給 agent

用 MCP 按下錄音。

把 agent 指到 http://localhost:5274/mcp。一輪大概長這樣：開始錄音 → 會議進行 → 帶 transcribe: true 停止 → 讀回逐字稿 → 把摘要寫進音檔旁邊的筆記。

start_recording按下錄音。只有在瀏覽器確認麥克風真的開了才回傳。
stop_recording停止並收尾；帶 transcribe: true 就順便跑 whisper。
read_transcript帶時間戳的 Markdown、純文字，或帶時間的片段。
search_transcripts跨所有逐字稿搜尋，回傳毫秒位移。
write_notes把摘要或待辦寫在音檔旁邊。
recorder_status現在有沒有在錄，以及有沒有工作室可以錄。

一段錄完的會議，以及 agent 會後寫進 notes.md 的摘要。

它不會謊報自己在錄音。start_recording 會等到工作室回報 MediaRecorder 真的跑起來才回傳。分頁被關掉、或麥克風被擋，agent 拿到的是一個講明原因的拒絕。一個對著沒在錄的錄音回「好了」的工具，是這種東西最糟糕的失敗方式——所以寧可拒絕。

03  開始使用

兩個指令，然後授權一次麥克風。

不裝任何其他東西也能錄。只有轉錄需要 whisper.cpp 跟 ffmpeg——缺哪個，doctor 會連修法一起印出來。

# 工作室在 :5274，MCP endpoint 在 /mcp
npx open-recording dev --mcp

# 選用——本機轉錄
brew install whisper-cpp ffmpeg
npx open-recording doctor
在 GitHub 上查看 npm 上的 @open-recording/core 其他工具
