The recording studio built for agents.

瀏覽器優先的錄音工具。分頁拿著麥克風，伺服器管著 session，轉錄交給你電腦裡的 whisper.cpp。音檔不會離開這台機器。

$ npx open-recording dev --mcp

工作室 — 每段錄音都是一張卡片，帶著逐字稿的開頭幾句

start_recording { title: "產品同步會議" }

→ 等瀏覽器確認麥克風 · 已開始錄音

01 · 為什麼

你按停止， agent 立刻就知道。

只有真的瀏覽器分頁拿得到麥克風，所以錄音一定發生在瀏覽器。但 session、檔案和逐字稿都放在 dev server——這樣人跟 agent 才是在操作同一台錄音機，而不是各自一台。

01 · 本機

音檔不會離開這台電腦

whisper.cpp 在你的 CPU 上跑完整個轉錄。不用 API key，斷網也照轉。

02 · 共用

誰按停止，另一邊都看得到

你在頁面上按停止，agent 那邊的狀態立刻跟著變。反過來也一樣。

03 · 檔案

打開資料夾就看得到全部

音檔、逐字稿、字幕、筆記都在同一個目錄裡。不需要透過這個工具，才讀得到自己的東西。

$ ls recordings/<id>/
audio.webm transcript.md
meta.json notes.md
04 · 字體

台北開的會，寫出來是繁體

Whisper 不管你講什麼都輸出簡體。設定之後 OpenCC 會逐詞轉過來，软件 變軟體不是軟件，時間戳一格都不動。

02 · 給 agent

用 MCP 按下錄音。 六個工具，一個 endpoint。

把 agent 指到 localhost:5274/mcp 就好。開會前叫它開始錄，散會叫它停止並轉錄，然後請它把摘要寫在音檔旁邊。

start_recording按下錄音。要等瀏覽器確認麥克風開了才回傳。
stop_recording停止並收尾。帶 transcribe: true 就順便跑 whisper。
read_transcript帶時間戳的 Markdown、純文字，或帶時間的片段。
search_transcripts跨所有逐字稿搜尋，附毫秒位移。
write_notes把摘要或待辦寫在音檔旁邊。
recorder_status現在有沒有在錄，以及有沒有工作室能錄。

它會拒絕，不會裝作有在錄。 分頁關掉了、麥克風被擋了，start_recording 回給 agent 的是講明原因的拒絕。散會才發現根本沒錄到，這種事只要發生一次就夠了。

錄完的會議 — 以及 agent 寫進 notes.md 的摘要

03 · 開始使用

錄下你的下一場會議。 一個指令，麥克風授權一次。

什麼都不裝也能錄。要轉錄才需要 whisper.cpp 跟 ffmpeg——缺哪個，doctor 會把安裝指令一起印給你。

# 工作室在 :5274，MCP endpoint 在 /mcp
$ npx open-recording dev --mcp

# 選用——本機轉錄
$ brew install whisper-cpp ffmpeg
$ npx open-recording doctor
✓ ffmpeg    ✓ whisper    ✓ model    ✓ script
